# 크롬 웹스토어 등록 초안

웹스토어 개발자 대시보드에 옮겨 적을 글을 모은다. 웹스토어 제출 준비 #84(S5~S7). 제출본은 11/24~25에 P3 기능을 고정한 뒤 만든다.

- 설명과 스크린샷에는 실제 북마크 제목·주소, 실제 이름·개인 메일을 넣지 않는다(샘플 북마크 프로필로 찍는다).
- 권한과 데이터 설명은 `extension/manifest.json`, `docs/privacy.md`와 같아야 한다. 하나를 고치면 셋을 함께 본다.

## 1. 단일 목적

> 새 탭을 크롬 북마크 중심 화면으로 바꿉니다.

## 2. 스토어 설명 (S6)

**자세한 설명**

## 3. 권한별 사용 이유 (S7)

`extension/manifest.json`의 권한과 같다(필수 4개, 선택 1개). 새 권한은 없다.

| 권한 | 대시보드에 적을 사용 이유 |
| --- | --- |
| `bookmarks` | 크롬 북마크를 새 탭에 앱과 폴더로 표시하고, 사용자가 확인한 정리·폴더 만들기·이동·삭제·끌어서 옮기기를 크롬 북마크에 반영합니다. |
| `storage` | 정리 기록(되돌리기용), 고정한 북마크, 확장 프로그램에서 북마크를 연 시각, 꾸미기 설정과 올린 사진을 이 기기의 로컬 저장소에 저장합니다. |
| `favicon` | 크롬이 저장해 둔 사이트 아이콘을 북마크 아이콘으로 보여 줍니다. 웹사이트에 접속하지 않습니다. |
| `search` | 새 탭의 웹 검색창에서 사용자가 크롬에 설정한 기본 검색엔진으로 검색합니다. |
| `topSites` (선택) | 사용자가 [고정하기]를 누르고 허락했을 때만 자주 방문한 사이트 목록을 읽어 고정할 북마크를 제안합니다. 목록은 저장하지 않습니다. |

**원격 코드:** 사용하지 않음. 스크립트·글꼴<!-- TODO: 11/23 글꼴이 빠지면 이 단어 삭제 -->·그림은 모두 확장 프로그램 안에 들어 있다.

## 4. 개인정보 보호 관행 입력 안내 (S5)

**"없음"으로 신고하지 않는다.** 웹스토어는 기기 안에서만 처리·저장하는 데이터도 '다루는 데이터'로 신고하라고 한다.

다루는 데이터 (모두 기기 안에서만 처리·저장, 밖으로 보내지 않음)

| 데이터 | 어디에 쓰나 |
| --- | --- |
| 크롬 북마크(제목, 주소, 폴더 구조, 저장한 시각, 마지막 사용 시각) | 새 탭 표시, 분류·정리, 검색, 잊고 있던 북마크 |
| 확장 프로그램에서 북마크를 연 시각 | 잊고 있던 북마크 고르기 |
| 자주 방문한 사이트 목록 (웹 기록, 선택 권한) | 허락했을 때만 고정 제안. 저장하지 않음 |
| 사용자가 올린 프로필 사진과 배경 사진 (줄인 사진만) | 계정 동그라미와 새 탭 배경 |

대시보드의 데이터 종류 9가지

| 데이터 종류 | 체크 | 해당하는 것 |
| --- | --- | --- |
| 웹 기록 | **체크** | 북마크 주소, 자주 방문한 사이트 |
| 사용자 활동 | **체크** | 북마크를 마지막으로 연 시각(크롬이 기록한 마지막 사용 시각, 확장 프로그램에서 연 시각) |
| 개인 식별 정보 | 안 함 | |
| 건강 정보 | 안 함 | |
| 금융 및 결제 정보 | 안 함 | |
| 인증 정보 | 안 함 | |
| 개인 통신 | 안 함 | |
| 위치 | 안 함 | |
| 웹사이트 콘텐츠 | 안 함 | |

사용자가 올린 사진은 9가지 종류 중 해당하는 것이 없어 대시보드에는 체크하지 않고, 개인정보처리방침(`docs/privacy.md` 3절·6절)에만 적는다.

세 가지 확인에 모두 체크

- [ ] 승인된 사용 사례 외의 목적으로 제3자에게 사용자 데이터를 판매하거나 전송하지 않음
- [ ] 항목의 단일 목적과 관련 없는 목적으로 사용자 데이터를 사용하거나 전송하지 않음
- [ ] 신용도를 판단하거나 대출 목적으로 사용자 데이터를 사용하거나 전송하지 않음

개인정보처리방침 URL

```
https://github.com/aix-team-5/aix_BaroLink_bookmark/blob/main/docs/privacy.md
```

## 6. 제출 패키지

제출 순서

1. 11/24 manifest version 0.1.0 → 1.0.0 (권한은 그대로)
2. 아래 명령으로 zip을 만든다
3. 테스트용 크롬 프로필에서 설치 시험 → 대시보드에 초안으로 올려 설치 시험 오류 확인 → 제출

- zip 안에는 `extension/` 폴더의 **내용만** 넣는다. `manifest.json`이 zip의 최상위(폴더 없이 바로)에 와야 한다. 목록 순서에서 첫 줄일 필요는 없다(`tar.exe -tf`로 보면 이름 순서라 `background.js`가 먼저 나온다).
- 저장소 맨 위에서 아래 한 줄을 PowerShell로 돌린다. 윈도우에 들어 있는 `tar`를 쓴다.

```powershell
tar.exe -a -cf barolink-1.0.0.zip -C extension *
```

- `Compress-Archive`는 쓰지 않는다. Windows PowerShell 5.1의 `Compress-Archive`는 zip 안 경로를 `js\store.js`처럼 역슬래시로 적는다(zip 규격은 `/`).
- 만든 zip은 저장소에 올리지 않는다. 풀어서 테스트용 크롬 프로필에 "압축해제된 확장 프로그램"으로 올려 `chrome://extensions`와 Console에 오류가 없는지 본다.
