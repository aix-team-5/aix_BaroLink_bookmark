# 크롬 웹스토어 등록 초안

웹스토어 개발자 대시보드에 옮겨 적을 글을 모은다. 웹스토어 제출 준비 #84(S5~S7). 제출본은 11/24~25에 P3 기능을 고정한 뒤 만든다.

- 설명과 스크린샷에는 실제 북마크 제목·주소, 실제 이름·개인 메일을 넣지 않는다(샘플 북마크 프로필로 찍는다).
- 권한과 데이터 설명은 `extension/manifest.json`, `docs/privacy.md`와 같아야 한다. 하나를 고치면 셋을 함께 본다.

## 1. 단일 목적

> 새 탭을 크롬 북마크 중심 화면으로 바꿉니다.

## 2. 스토어 설명 (S6)

**요약** (manifest의 `description`과 같게 둔다. 132자 이하)

> 크롬 북마크를 새 탭에 앱과 앱 폴더로 보여 주고, 잊고 있던 북마크를 다시 꺼내 주며, 한 번 확인으로 정리해 주는 새 탭 북마크 도구

**자세한 설명**

```
바로링크는 새 탭을 크롬 북마크 중심 화면으로 바꿉니다. 북마크를 휴대폰 앱처럼 아이콘과 앱 폴더로 보여 주고, 쌓이기만 하던 북마크를 정리하도록 돕습니다.

주요 기능
• 북마크를 앱처럼: 크롬 북마크를 아이콘과 앱 폴더로 새 탭에 보여 줍니다.
• 한 번 확인으로 정리: 사이트 종류에 따라 폴더를 제안하고, 확인을 누른 것만 옮깁니다. 정리 기록에서 언제든 되돌릴 수 있습니다.
• 잊고 있던 북마크: 크롬이 기록한 마지막 사용 시각과 확장 프로그램에서 연 시각으로 오래 안 연 북마크를 다시 보여 줍니다.
• 고정 제안: 사용자가 허락했을 때만 자주 방문한 사이트를 사용해 화면 아래에 고정할 북마크를 제안합니다.
• 끌어서 옮기기: 앱을 끌어 폴더에 넣거나 폴더 안에서 순서를 바꿉니다.
• 내 정보와 꾸미기: 북마크 동기화 상태와 북마크·폴더 개수를 보고, 색상·배경·글꼴과 프로필 사진을 고릅니다.
• 검색: 북마크를 찾거나, 크롬에 설정한 기본 검색엔진으로 웹을 검색합니다.

데이터
북마크와 설정, 올린 사진은 모두 이 기기 안에서만 처리하고 저장하며, 밖으로 보내지 않습니다. 서버, 회원가입, 광고, 분석 도구가 없습니다. 웹 검색창에 입력한 검색어만 크롬의 기본 검색엔진으로 전달됩니다.

개인정보처리방침: https://github.com/aix-team-5/aix_BaroLink_bookmark/blob/main/docs/privacy.md
```


## 3. 권한별 사용 이유 (S7)

`extension/manifest.json`의 권한과 같다(필수 4개, 선택 1개). 새 권한은 없다.

| 권한 | 대시보드에 적을 사용 이유 |
| --- | --- |
| `bookmarks` | 크롬 북마크를 새 탭에 앱과 폴더로 표시하고, 사용자가 확인한 정리·폴더 만들기·이동·삭제·끌어서 옮기기를 크롬 북마크에 반영합니다. |
| `storage` | 정리 기록(되돌리기용), 고정한 북마크, 확장 프로그램에서 북마크를 연 시각, 꾸미기 설정과 올린 사진을 이 기기의 로컬 저장소에 저장합니다. |
| `favicon` | 크롬이 저장해 둔 사이트 아이콘을 북마크 아이콘으로 보여 줍니다. 웹사이트에 접속하지 않습니다. |
| `search` | 새 탭의 웹 검색창에서 사용자가 크롬에 설정한 기본 검색엔진으로 검색합니다. |
| `topSites` (선택) | 사용자가 [고정하기]를 누르고 허락했을 때만 자주 방문한 사이트 목록을 읽어 고정할 북마크를 제안합니다. 목록은 저장하지 않습니다. |

**원격 코드:** 사용하지 않음. 스크립트·글꼴·그림은 모두 확장 프로그램 안에 들어 있다.

## 4. 개인정보 보호 관행 입력 안내 (S5)

**"없음"으로 신고하지 않는다.** 웹스토어는 기기 안에서만 처리·저장하는 데이터도 '다루는 데이터'로 신고하라고 한다.

다루는 데이터 (모두 기기 안에서만 처리·저장, 밖으로 보내지 않음)

| 데이터 | 어디에 쓰나 |
| --- | --- |
| 크롬 북마크(제목, 주소, 폴더 구조, 저장한 시각, 마지막 사용 시각) | 새 탭 표시, 분류·정리, 검색, 잊고 있던 북마크 |
| 확장 프로그램에서 북마크를 연 시각 | 잊고 있던 북마크 고르기 |
| 자주 방문한 사이트 목록 (웹 기록, 선택 권한) | 허락했을 때만 고정 제안. 저장하지 않음 |
| 사용자가 올린 프로필 사진과 배경 사진 (줄인 사진만) | 계정 동그라미와 새 탭 배경 |

대시보드의 데이터 종류 9가지

| 데이터 종류 | 체크 | 해당하는 것 |
| --- | --- | --- |
| 웹 기록 | **체크** | 북마크 주소, 자주 방문한 사이트 |
| 사용자 활동 | **체크** | 북마크를 마지막으로 연 시각(크롬이 기록한 마지막 사용 시각, 확장 프로그램에서 연 시각) |
| 개인 식별 정보 | 안 함 | |
| 건강 정보 | 안 함 | |
| 금융 및 결제 정보 | 안 함 | |
| 인증 정보 | 안 함 | |
| 개인 통신 | 안 함 | |
| 위치 | 안 함 | |
| 웹사이트 콘텐츠 | 안 함 | |

사용자가 올린 사진은 9가지 종류 중 해당하는 것이 없어 대시보드에는 체크하지 않고, 개인정보처리방침(`docs/privacy.md` 3절·6절)에만 적는다.

세 가지 확인에 모두 체크

- [ ] 승인된 사용 사례 외의 목적으로 제3자에게 사용자 데이터를 판매하거나 전송하지 않음
- [ ] 항목의 단일 목적과 관련 없는 목적으로 사용자 데이터를 사용하거나 전송하지 않음
- [ ] 신용도를 판단하거나 대출 목적으로 사용자 데이터를 사용하거나 전송하지 않음

개인정보처리방침 URL

```
https://github.com/aix-team-5/aix_BaroLink_bookmark/blob/main/docs/privacy.md
```

로그인하지 않은 창에서 이 주소가 열리는지 확인한다. 시행일(`2026년 11월 __일`)은 제출일에 채운다.

### 스크린샷 찍는 법

실제 북마크·이름·메일이 보이지 않게 테스트용 크롬 프로필에서 찍는다. 평소 쓰는 프로필은 쓰지 않는다.

1. 테스트용 크롬 프로필에 확장 프로그램을 "압축해제된 확장 프로그램"으로 올린다.
2. `tests/sample-100.html`을 북마크로 가져온다(북마크 관리자 → 북마크 가져오기). 실제 북마크·이름·메일이 없는 샘플이다.
3. 새 탭을 연다.
4. F12로 개발자 도구를 열고, 기기 툴바(Ctrl+Shift+M)에서 크기를 1280×800, DPR을 1로 맞춘다(DPR이 1이 아니면 사진이 2560×1600처럼 커진다).
5. Ctrl+Shift+P → "Capture screenshot"을 고른다. PNG로 내려받아진다.
6. 받은 파일에 실제 북마크·이름·메일이 보이지 않는지 다시 본다.

찍은 화면 (모두 1280×800). 웹스토어는 5장까지라 1·3·4·6·7번을 올리고, 2·5번은 발표 자료에 쓴다.

| 번호 | 화면 | 파일 | 쓰는 곳 |
| --- | --- | --- | --- |
| 1 | 새 탭 전체(정리 제안 카드·내 폴더·고정됨) | `store/screenshot-1-newtab.png` | **웹스토어** |
| 2 | 정리 자세히 보기 팝업 | `store/screenshot-2-organize-detail.png` | 발표 자료용 |
| 3 | 정리 결과 안내와 정리된 내 폴더 | `store/screenshot-3-organize-result.png` | **웹스토어** |
| 4 | 잊고 있던 북마크 팝업 | `store/screenshot-4-forgotten.png` | **웹스토어** |
| 5 | 폴더 팝업 안에서 앱 순서 바꾸기 | `store/screenshot-5-folder-reorder.png` | 발표 자료용 |

## 6. 제출 패키지

제출 순서

1. 11/24 manifest version 0.1.0 → 1.0.0 (권한은 그대로)
2. 아래 명령으로 zip을 만든다
3. 테스트용 크롬 프로필에서 설치 시험 → 대시보드에 초안으로 올려 설치 시험 오류 확인 → 제출

- zip 안에는 `extension/` 폴더의 **내용만** 넣는다. `manifest.json`이 zip의 최상위(폴더 없이 바로)에 와야 한다. 목록 순서에서 첫 줄일 필요는 없다(`tar.exe -tf`로 보면 이름 순서라 `background.js`가 먼저 나온다).
- 저장소 맨 위에서 아래 한 줄을 PowerShell로 돌린다. 윈도우에 들어 있는 `tar`를 쓴다.

```powershell
tar.exe -a -cf barolink-1.0.0.zip -C extension *
```

- `Compress-Archive`는 쓰지 않는다. Windows PowerShell 5.1의 `Compress-Archive`는 zip 안 경로를 `js\store.js`처럼 역슬래시로 적는다(zip 규격은 `/`).
- 만든 zip은 저장소에 올리지 않는다. 풀어서 테스트용 크롬 프로필에 "압축해제된 확장 프로그램"으로 올려 `chrome://extensions`와 Console에 오류가 없는지 본다.

## 7. 지금 대시보드에 초안으로 넣기 (제출 버튼은 누르지 않음)

개발자 계정은 등록을 마쳤다. 지금 main으로 초안을 만들어 두고, 11/24 기능 고정 뒤에 바꿔서 제출한다.

1. **zip 올리기.** 지금 main으로 6절의 명령을 돌려 zip을 만든다. 이름만 `barolink-draft.zip`으로 바꾸고 manifest의 version은 그대로 둔다. 대시보드에서 새 항목 → zip 업로드. 초안이 생기고 설치 시험이 바로 돈다.

   ```powershell
   tar.exe -a -cf barolink-draft.zip -C extension *
   ```

2. **스토어 등록정보.** 2절의 요약과 자세한 설명, 언어 한국어, 카테고리는 생산성 계열에서 고른다. 아이콘(`extension/icons/icon128.png`)과 작은 프로모션 타일(`store/promo-small-440x280.png`), 스크린샷 5장(1·3·4·6·7번)을 이 순서로 올린다.
3. **개인정보 보호.** 1절의 단일 목적, 3절의 권한별 사용 이유와 원격 코드, 4절의 데이터("없음"으로 신고하지 않음)와 세 가지 확인, 개인정보처리방침 URL을 넣는다.
4. **배포.** 공개 범위와 지역은 팀과 정한다.
5. **"초안 저장"까지만 누른다.** 제출하지 않는다. 11/24 기능 고정 뒤 6절대로 1.0.0 zip을 새로 올린 뒤 제출한다.
6. **계정 설정.** 연락처 이메일 확인과 판매자(트레이더) 여부 신고가 안 돼 있으면 같이 한다.
