# 📌 프로젝트 개요

- **한 줄 정의:** 브라우저 구석에 묻혀 잊히는 크롬 북마크를, 매일 여는 새 탭에 휴대폰 홈 화면처럼 앱과 앱 폴더로 보여 주고, 잊고 있던 북마크를 다시 꺼내 주며, 한 번 확인만으로 크롬 북마크에 실제로 정리해 주는 새 탭 북마크 도구 (크롬 기본 검색은 그대로)
- **타겟 사용자:** PC 크롬에서 북마크를 쓰지만 폴더 정리는 하지 않는 대학생 (설문: 북마크 사용자 26명 중 16명이 폴더를 만들지 않음)
- **핵심 가치:** 북마크가 **눈에 보이는 곳에 있어서 잊히지 않고**, 이름이 기억나지 않아도 **사이트와 종류로 알아볼 수 있으며**, 정리는 **한 번 확인하고 누르는 것만으로** 끝나는 북마크
- **기술 스택:** 크롬 확장 프로그램 (Manifest V3, 크롬 134 이상) · HTML / CSS / JavaScript (빌드 도구 없음, ES 모듈) · 백그라운드 서비스 워커 (북마크 변경 감지) · SortableJS (확장 프로그램 폴더에 파일로 포함, CDN 사용 불가) · 서버·DB·AI 없음 (크롬 북마크 + chrome.storage.local) · 권한: bookmarks, storage, favicon, search (선택 권한: topSites — 고정 제안에서 사용자가 [고정하기]를 누를 때만 요청)
- **범위:** 한 PC 기준. 폴더는 크롬 동기화로 다른 기기에도 보이지만, 정리 기록·직접 옮김 기억·고정 목록은 이 PC에만 저장한다.

        5. 정리 결과를 근거와 함께 보여 주고, 확인하면 크롬 북마크에 실제 폴더로 남긴다.

    ## 2. 핵심 개념 정리

    ## 2-1. 원본 북마크와 자동 동기화

    원본 북마크는 사용자가 크롬에 저장한 북마크 그 자체이다. 본 서비스는 원본을 서버로 복사하지 않고 크롬 북마크를 그대로 읽으며, 크롬에서 저장·수정·삭제·이동한 내용이 새 탭에 저절로 반영된다. 다른 기기에서 저장한 북마크는 사용자의 크롬 로그인 동기화로 들어온다.

    ## 2-2. 앱과 앱 폴더

    앱은 북마크 하나를 사이트 아이콘과 이름으로 보여 주는 단위이고, 앱 폴더는 여러 앱을 묶는 단위이다. **앱 폴더 = 크롬 북마크 폴더**이므로, 새 탭에서는 앱 폴더로 보이고 크롬 북마크 관리자에서는 같은 이름의 일반 폴더로 보인다. 사용자가 원래 만들어 둔 크롬 폴더도 앱 폴더로 보여 준다.

    ## 2-3. 잊고 있던 북마크 (재발견)

    설문에서 "북마크해 둔 사실 자체를 잊는다", "북마크가 눈에 안 띈다"는 응답이 나왔다. 그래서 오래 열지 않은 북마크를 새 탭이 먼저 꺼내서 보여 준다.

    **형태: 우리 화면에만 있는 폴더.** 새 탭 앱 폴더 줄의 맨 앞에 "잊고 있던 북마크" 폴더를 보여 주고, 누르면 오래 안 연 북마크가 팝업으로 펼쳐진다. 북마크는 **실제로 옮기지 않고 제자리에 그대로 둔다.** 크롬 북마크 관리자에는 나타나지 않으므로 정리 결과나 정리 기록과 충돌하지 않는다.

    | 쓰는 시각 | 언제 기록되나 | 쓰는 조건 |
    | --- | --- | --- |
    | 우리 새 탭에서 앱을 눌러 연 시각 (lastOpenedByUs, 우리가 직접 기록) | 우리 화면에서 열 때. 이때 크롬의 마지막 사용 시각은 바뀌지 않는다 | 아래 값과 비교해 더 최근 값을 쓴다 |
    | 크롬의 마지막 사용 시각 (dateLastUsed, 크롬 114 이상) | 크롬 북마크바·북마크 관리자에서 열 때 | 위 값과 비교해 더 최근 값을 쓴다 |
    | 저장한 시각 (dateAdded) | 북마크를 저장할 때 | 위 둘이 모두 없을 때만 쓴다 |

    위 두 시각이 모두 없을 때만 "연 기록 없음"을 표시하고, 그 외에는 "2개월 전에 열어 봄"처럼 아는 만큼만 표시한다. ("안 열어 봄"이라고 쓰지 않는 이유: 주소창으로 여는 북마크는 기록이 남지 않아, 실제로는 자주 여는 북마크에 틀린 말이 붙는다. 10월 6일 변경) 크롬 방문 기록(history 권한)은 "방문 기록 읽기 및 변경" 경고가 뜨고 민감한 정보에 접근하므로 쓰지 않는다. 실험 결과(Chromium 141), dateLastUsed는 북마크바와 북마크 관리자에서 열 때만 바뀌고 주소창 입력·링크·우리 새 탭으로 열 때는 바뀌지 않았다. 그래서 주소창으로만 여는 북마크는 "안 연 것"으로 보일 수 있다. (알려진 한계) 설치 첫날에는 이런 북마크까지 대부분 후보가 되므로, 한 번에 8개까지만 보여 준다.

    **눈에 띄게 하는 장치:** 폴더가 북마크를 다시 숨기지 않도록 앱 폴더 줄 **맨 앞**에 두고, 다른 폴더와 구별되는 색·모양(확정 시안: 어두운 색 카드)을 쓰며, **개수 배지**(표시하는 개수, 최대 8)를 단다. 후보가 하나도 없으면 폴더를 숨긴다.

    ## 2-4. 정리 원리

    > 흩어진 북마크를 사이트 종류로 분류해, **많은 카테고리부터 3~6개 폴더만** 한 번 확인 후 만들고, 나머지와 새 북마크는 새 탭에 계속 보이다가 [정리하기]로 추천 폴더나 원하는 폴더에 넣는다. **사용자가 만든 폴더와 북마크바에서 요즘 쓰는 북마크는 건드리지 않고**, 되돌릴 수 있도록 원래 위치를 기록한다. 폴더를 만들 수 없을 만큼 적으면 폴더 대신 **고정**을 제안한다.

    ## 2-5. 정리 대상

    - **정리 대상:** 북마크바·기타 북마크·모바일 북마크 바로 아래에 폴더 없이 흩어져 있는 북마크 전부
    - **기본으로 건드리지 않는 것:** 사용자가 직접 만든 폴더(자세히 보기에서 체크하면 포함 가능), **북마크바에서 최근 30일 안에 눌러 연 북마크**(요즘 쓰는 북마크)
    - **요즘 쓰는 북마크 보호:** 크롬의 마지막 사용 시각(dateLastUsed)은 북마크바에서 열 때 바뀌므로, 북마크바에서 실제로 눌러 쓰는 북마크만 정확히 가려낼 수 있다. 이 북마크들은 폴더에 넣지 않고 제자리에 두며, 카테고리 개수를 셀 때도 뺀다. (카드의 숫자와 실제로 폴더에 들어가는 개수가 같아야 하기 때문) 기준이 잊고 있던 북마크와 같은 30일이라 두 규칙이 겹치지 않는다.
    - **북마크바를 넣은 이유 (10월 6일 변경):** 크롬 별 버튼의 기본 저장 위치가 북마크바라서, 폴더를 만들지 않는 사용자의 북마크는 대부분 북마크바에 있다. 북마크바를 빼면 정리 대상이 거의 남지 않는다. 자세히 보기에서 북마크바를 뺄 수 있다.
    - **빼는 것:** javascript: 북마클릿, chrome:// 주소
    - **다시 옮기지 않는 것:** 사용자가 우리 화면이나 크롬 북마크 관리자에서 직접 옮긴 북마크

    ## 2-6. 분류: 북마크 하나를 어느 카테고리로 보내나

    주소와 크롬이 저장한 제목만 보고, 위에서부터 확인해 **처음 맞는 곳에서 멈춘다.** 북마크 하나는 카테고리 하나에만 들어간다.

    | 순서 | 기준 | 예시 |
    | --- | --- | --- |
    | ① | 사이트 분류표 (세부 주소 단위) | youtube.com → 영상, blog.naver.com → 블로그·글, docs.google.com → 문서·협업 |
    | ② | 주소 끝 규칙 | .ac.kr, .edu → 학교 |
    | ③ | 제목 키워드 | 제목에 "채용" → 취업 |
    | ④ | 해당 없음 | 분류 안 됨 (폴더 밖에 그대로) |

    ## 2-7. 카테고리 정의

    카테고리는 **사이트의 종류**로만 정의한다. 내용(무슨 영상인지)으로 판단하지 않으므로 사이트 하나는 항상 한 카테고리로만 간다. 분류표는 코드가 아닌 데이터 파일(categories.json)로 관리하고, 자세한 정의와 경계 규칙은 `category-definitions.md`에 있다(10월 7일). 뉴스·위키·검색 결과처럼 "분류하지 않는 사이트"는 제목 키워드를 보지 않고 분류 안 됨으로 둔다.

    | 카테고리 | 정의 | 대표 사이트 | 경계 규칙 |
    | --- | --- | --- | --- |
    | 학교 | 대학·학교가 운영하는 사이트 | .ac.kr 전체, 에브리타임 | 주소가 .ac.kr이면 내용과 관계없이 학교 |

    | 온라인 강의 | 강의를 판매·제공하는 플랫폼 | 인프런, 유데미, 클래스101 | 영상이 있어도 강의 플랫폼이면 여기 |
    | 블로그·글 | 개인이 글을 올리는 사이트 | 네이버 블로그, 티스토리, velog, 브런치 | 주제와 관계없이 블로그면 여기 |

    ## 2-8. 폴더 만들기: 몇 개, 몇 개씩

    분류가 끝난 뒤 카테고리별 개수를 세고, **북마크가 많은 카테고리부터** 아래 개수만큼 폴더로 만든다.

    | 정리 대상 북마크 | 만드는 폴더 |
    | --- | --- |
    | 10개 미만 | 폴더를 만들지 않음 → 고정 제안 |
    | 10~29개 | 최대 3개 |
    | 30~59개 | 최대 4개 |
    | 60~99개 | 최대 5개 |
    | 100개 이상 | 최대 6개 |

    - 폴더 하나에는 **최소 3개**. 3개 미만인 카테고리는 폴더로 만들지 않는다.
    - **기타 폴더는 만들지 않는다.** 폴더에 안 들어간 북마크는 새 탭에서 폴더 아래 앱으로 계속 보인다. 분류가 애매한 북마크가 폴더 속에 숨지 않게 하기 위해서다.
    - 폴더는 **북마크바 맨 뒤**에 만들고, 북마크바에 같은 이름의 폴더가 있으면 그 폴더를 쓴다. 기타 북마크에 흩어져 있던 북마크도 같은 폴더로 들어가므로 폴더는 한 벌만 생긴다. 북마크가 원래 있던 자리에 폴더가 생겨 사라진 느낌이 없고, 확장 프로그램을 지워도 정리된 폴더가 늘 보던 곳에 남는다. 맨 뒤에 만드는 이유는 늘 누르던 북마크의 순서를 바꾸지 않기 위해서다. (10월 6일 변경. 이전: 기타 북마크 안)
    - 북마크바·기타 북마크·모바일 북마크는 폴더 ID가 아니라 크롬이 알려 주는 **폴더 종류(folderType)**로 구별한다. 크롬 134부터 같은 종류의 폴더가 계정용과 이 PC 전용으로 두 개 보일 수 있으므로, 두 개면 **동기화되는 쪽(syncing)**만 정리 대상으로 삼고 그쪽 북마크바에 폴더를 만든다. (다른 기기에서도 폴더가 보이게 하기 위해서. 기타 북마크가 두 개인 경우는 확인했고, 북마크바가 두 개인 경우는 개발 첫 주에 확인한다)
    - 폴더가 **20개를 넘으면** 세부 폴더를 제안한다. (P3)

    ## 2-9. 폴더를 만들 수 없을 때: 고정 제안

    설문에서 폴더를 안 만드는 사용자의 절반이 북마크 20개 이하였고, 요즘 쓰는 북마크와 사용자 폴더를 빼면 정리 대상은 더 줄어든다. 그래서 아래 경우를 "폴더를 만들 수 없는 상황"으로 보고, 폴더 대신 고정을 제안한다.

    - 정리 대상이 **10개 미만**일 때
    - 10개 이상이어도 **3개 이상 모인 카테고리가 하나도 없을** 때

    **제안 카드**

    > **북마크들이 서로 달라서 아직 묶을 폴더가 없어요**
    > 대신 자주 쓰는 북마크 5개를 고정할까요?
    > [고정하기] [고르기] [나중에]

    **자주 쓰는 북마크 고르는 순서**

    1. 크롬의 "자주 방문한 사이트" 목록(chrome.topSites, 크롬 기본 새 탭의 바로가기와 같은 목록)을 가져온다.
    2. 이 목록과 **같은 사이트**인 북마크를 목록 순서대로 먼저 고른다.
    3. 5개가 안 되면 남은 자리는 최근에 연 순(우리가 기록한 연 시각 → 크롬의 마지막 사용 시각)으로 채운다.

    **권한 처리:** topSites 권한은 설치할 때 받지 않고 **선택 권한(optional_permissions)**으로 둔다. 사용자가 [고정하기]를 누를 때만 "가장 자주 방문하는 웹사이트 목록 읽기" 허락을 요청한다. 폴더를 만들 수 있는 대부분의 사용자는 이 경고를 볼 일이 없다. 허락하지 않거나 목록이 비어 있으면(방문 기록을 지운 경우 등) 최근에 연 순으로만 고른다.

    **개인정보:** 자주 방문한 사이트 목록은 받아서 북마크와 비교하는 데만 쓰고, 저장하거나 외부로 보내지 않는다. 허락 요청 화면과 카드에 "자주 방문한 사이트 목록도 이 컴퓨터 안에서만 써요"를 밝힌다.

    나머지 북마크는 앱으로 그대로 보이고, 잊고 있던 북마크 폴더도 그대로 동작한다. 북마크바가 기본 정리 대상이 되었으므로 "북마크바에 N개가 있어요. 함께 정리할까요?"는 묻지 않는다(10월 6일 삭제). 나중에 북마크가 늘어 폴더를 만들 수 있게 되면 정리를 제안한다.

    ## 2-10. 처음 정리: 첫 화면에서 한 번 확인

    설치 후 첫 새 탭에 카드 하나가 뜬다. **설치만 해서는 크롬 북마크가 바뀌지 않는다.**

    > **북마크를 이렇게 묶어 볼까요?**
    > 영상 8 · 학교 6 · 블로그·글 5 · 개발 3 · 나머지 8개는 그대로
    > 직접 만든 폴더와 북마크바에서 요즘 쓰는 북마크는 그대로 둬요
    > [정리하기] [자세히 보기] [나중에]

    [자세히 보기]에서는 폴더별 근거와 들어갈 북마크를 보고, 폴더 빼기·이름 바꾸기·북마크별 폴더 바꾸기·북마크바 제외·사용자 폴더 포함을 할 수 있다(고치기는 P2, P1에서는 보기만). 제목 키워드로 정해진 북마크에는 "확인 필요" 표시를 붙인다.

    ## 2-11. 이후: 새 북마크가 생겼을 때

    1. 별 버튼으로 저장하면 새 탭의 모든 북마크에 **"새로" 표시**와 함께 바로 나타난다.
    2. 위쪽 **[정리하기 · 3]** 버튼에 정리 안 된 새 북마크 수가 표시된다. 강제로 뜨는 알림은 없다.
    3. [정리하기]를 누르면 새 북마크마다 **추천 폴더**가 골라진 창이 뜬다.
    4. 추천 폴더가 골라진 그대로, 또는 폴더를 직접 바꾼 뒤 **[정리하기]**로 한 번에 정리한다. 맞는 폴더가 없는 북마크는 "그대로 두기"가 골라져 있다.
    5. 폴더 밖에 같은 카테고리가 3개 이상 모이면 같은 창에서 "폴더로 만들까요?"를 제안한다. (최대 폴더 수 안에서)

    ## 2-12. 기록과 직접 옮김 처리

    정리할 때마다 북마크별로 **원래 위치(폴더와 순서)와 옮긴 폴더**, 그리고 **정리 직전 원래 폴더의 전체 순서와 그 정리가 새로 만든 폴더 목록**을 chrome.storage.local에 저장한다. 이 기록으로 정리 기록 화면과 되돌리기를 만든다. 원래 순서는 첫 북마크를 옮기기 전에 한꺼번에 읽어 둔다. 정리 이유는 저장하지 않는다. (분류 근거는 정리 전 자세히 보기에서만 계산해 보여 준다)

    | 누가 옮겼나 | 어떻게 알아내나 | 처리 |
    | --- | --- | --- |
    | 우리 화면에서 사용자가 옮김 (우클릭, 드래그) | 크롬의 이동 알림(onMoved)을 서비스 워커가 받음. "옮기는 중" 표시가 없음 | "직접 옮김"으로 기록 |
    | 크롬 북마크 관리자에서 사용자가 옮김 | 위와 같음 | "직접 옮김"으로 기록 |
    | 우리 정리 기능이 옮김 (정리 적용, 되돌리기) | 이동 알림이 왔을 때 "옮기는 중" 표시가 있음 | 직접 옮김으로 기록하지 않음 (정리 기록에만 남김) |

    "직접 옮김"으로 기록된 북마크는 다음 정리에서 다시 옮기지 않는다.

    **새 탭이 닫혀 있을 때의 감지:** 새 탭 화면의 코드는 새 탭이 열려 있을 때만 동작하므로, 크롬의 이동 알림은 **백그라운드 서비스 워커**가 받아 chrome.storage.local에 기록한다. 우리 정리 기능은 옮기기 전에 "옮기는 중" 표시(옮길 북마크와 목적지 폴더, 표시한 시각)를 먼저 저장해 두고, 서비스 워커는 같은 북마크가 같은 목적지로 1분 안에 옮겨진 경우를 직접 옮김으로 기록하지 않는다. 표시는 옮긴 뒤에 지우지 않고 1분 뒤 만료시킨다. 옮긴 직후에 지우면 서비스 워커가 알림을 받기 전에 표시가 사라져, 우리 정리가 직접 옮김으로 잘못 기록되고 되돌리기가 막힌다. (실제 크롬에서 확인)

    **저장 항목은 한쪽만 쓴다:** 새 탭과 서비스 워커가 같은 저장 항목을 동시에 고치면 한쪽 값이 사라진다(실험: 120번 중 91개만 남음). 그래서 직접 옮긴 북마크와 새 북마크는 서비스 워커만, 나머지는 새 탭만 쓴다. 저장 항목 전체는 기술 설계의 "ERD / DB 스키마"에 있다.

    ## 2-13. AI를 쓰지 않는 이유

    1. **개발 문제:** 외부 AI를 쓰려면 API 키를 숨길 서버와 사용료가 필요하다.
    2. **개인정보 문제:** 북마크에는 은행·학교·회사 내부 주소와 관심사가 담겨 있어, AI로 보내는 순간 외부 유출 위험이 생긴다.
    3. **크롬 내장 AI의 한계:** 외부 전송은 없지만, 사용자 컴퓨터에 수 GB의 모델을 내려받아야 하고 사양이 낮으면 쓸 수 없으며, 한국어를 공식 지원하지 않는다.
    4. **결과가 매번 달라짐:** 같은 북마크가 정리할 때마다 다른 폴더로 갈 수 있고, 왜 그렇게 나눴는지 설명할 수 없으며, 정확도를 반복해서 재고 고치기 어렵다.

    그래서 이 컴퓨터 안에서, 항상 같은 기준으로, 분류 근거를 설명할 수 있는 규칙 기반 정리를 택했다. 크롬 내장 AI가 한국어를 공식 지원하고, 분류표로 나누지 못하는 북마크 비율이 계속 높게 나오면, 분류 안 된 북마크에만 사용자가 켰을 때 보조로 쓰는 방식을 다시 검토한다.

    ## 2-14. 두 가지 검색

    | 구분 | 웹 검색 | 북마크 검색 |
    | --- | --- | --- |
    | 찾는 대상 | 인터넷 | 내 북마크 |
    | 위치 | 새 탭 가운데 위 (크롬 기본 새 탭의 검색창 자리) | 모든 북마크 영역 위 |
    | 동작 | 크롬에 설정한 기본 검색엔진으로 검색 | 제목·주소로 찾고, 결과를 모든 북마크 영역에 바로 보여 줌 |
    | 안내 문구 | "웹 검색" | "북마크 제목 또는 주소로 검색" |

    두 검색창은 서로 연동하지 않는다. 위쪽은 웹만, 아래쪽은 북마크만 찾는다. (10월 6일 확정)

    ## 3. 핵심 기능 상세 정리

    ## 3-1. 크롬 북마크 자동 동기화 (P1)

    - 설치 후 추가 조작 없이 크롬 북마크 전체를 읽어 오며, 개수는 크롬 북마크 관리자와 같다.
    - 크롬 별 버튼으로 저장한 북마크가 새로고침 없이 나타나고, 삭제·수정·이동도 반영된다. (onCreated, onRemoved, onChanged, onMoved)

    ---

    ## 3-2. 앱 형태 북마크와 앱 폴더 (P1 · 폴더 만들기·이름 바꾸기·삭제는 P2)

    - 북마크는 사이트 아이콘과 이름이 있는 앱으로 표시되고, 클릭하면 현재 탭에서 페이지가 열린다.
    - 사이트 아이콘은 크롬이 보관한 파비콘(대부분 16~32px)을 쓴다. 크게 늘리면 흐려지므로 **색 타일 위에 작은 아이콘**을 올리는 형태로 그리고, 이 PC에서 방문한 적이 없어 아이콘이 없는 사이트는 **제목의 첫 글자**로 대신한다. 실제 파비콘은 색이 있는 그림이라 진한 타일 위에서는 잘 안 보일 수 있으므로, 아이콘이 있을 때는 흰색이나 연한 타일을 쓴다(구현할 때 확인).
    - chrome://·file:// 주소의 북마크는 일반 링크로 열리지 않으므로 chrome.tabs.create()로 연다.
    - 앱 폴더는 안에 든 앱의 색이 작은 칸으로 비쳐 보이는 아이콘과 이름·개수로 표시된다.
    - 앱 폴더를 누르면 새 탭 위에 팝업으로 펼쳐진다. 팝업은 한 줄에 4개씩(좁은 창에서는 2개씩) 보여 주고, 넘치면 팝업 안에서 스크롤한다. 이름 바꾸기와 삭제를 할 수 있다(P2).
    - 폴더를 삭제하면 안의 북마크는 지우지 않고 밖으로 꺼낸 뒤 폴더만 삭제한다.

    ---

    ## 3-3. 잊고 있던 북마크 (P1, 핵심 해결책)

    - 새 탭 앱 폴더 줄 맨 앞에 "잊고 있던 북마크" 폴더를 다른 폴더와 구별되는 모양과 개수 배지로 보여 준다. 크롬 북마크에는 만들지 않는 우리 화면 전용 폴더다.
    - 폴더를 누르면 2-3의 기준으로 고른 북마크가 오래 안 연 순서로 **8개까지** 펼쳐지고, 각 앱에 "6개월 전 저장 · 5개월 전에 열어 봄" 또는 "3개월 전 저장 · 연 기록 없음"처럼 표시한다.
    - 앱마다 할 수 있는 것: 열기(아이콘이나 제목을 누름. 열면 폴더에서 빠짐), 고정하기(고정됨에 추가하고 폴더에서 빠짐, P2), 이제 안 봐도 됨(다시 나오지 않음, 실수했을 때 6초 동안 되돌리기), 어디 있는지 보기(들어 있는 앱 폴더를 열어 보여 줌)
    - 우리 새 탭에서 앱을 열 때마다 연 시각을 chrome.storage.local에 기록한다. (lastOpenedByUs)
    - 후보가 없으면 폴더를 숨긴다.

    ---

    ## 3-4. 분류, 첫 정리, 적용 (P1, 핵심 차별점)

    - 2-5 ~ 2-10의 규칙대로 분류하고 폴더 계획을 세운다.
    - 첫 새 탭에서 정리 카드(또는 고정 제안 카드)를 한 번 보여 주고, [정리하기]를 누른 뒤에만 크롬 북마크를 바꾼다.
    - chrome.bookmarks.create()로 북마크바 맨 뒤에 폴더를 만들고 chrome.bookmarks.move()로 옮긴다. 비게 된 폴더는 지우지 않는다.
    - 적용 후 "폴더 4개를 만들고 북마크 22개를 넣었어요 · [되돌리기]"처럼 짧게 결과를 알려 준다. 이 안내는 12초 동안 보이고, 사용자가 닫을 수 있다.
    - 북마크별 원래 위치(폴더와 순서)와 옮긴 폴더, 정리 직전 원래 폴더의 전체 순서, 새로 만든 폴더 목록을 기록한다. (2-12)

    ---

    ## 3-5. 고정됨 (독)과 고정 제안 (P2)

    - 고정한 북마크가 화면 아래에 떠 있는 고정됨 영역(독)에 표시되고, 스크롤해도 그 자리에 있으며, 새 탭을 다시 열어도 유지된다. 최대 8개까지 고정할 수 있고, 고정해도 크롬 북마크의 위치는 바뀌지 않는다.
    - 고정됨 영역은 화면 맨 아래에서 72px 이상 띄운다. 크롬이 확장 프로그램 새 탭의 맨 아래 약 56px에 자체 띠를 붙이기 때문이다.
    - 고정됨의 [+]를 누르면 "고정할 북마크 고르기" 창이 열리고, 폴더 안의 북마크까지 고를 수 있다. 8개가 차면 [+]를 숨긴다. 고정된 앱에 마우스를 올리면 이름과 고정 해제(x) 버튼이 보인다.
    - 폴더를 만들 수 없을 때는 자주 쓰는 북마크 최대 5개를 고정하자고 제안한다. 크롬 자주 방문한 사이트와 겹치는 북마크를 먼저 고르고, 부족하면 최근에 연 순으로 채운다. topSites 권한은 [고정하기]를 누를 때만 요청한다. 고를 수 있는 북마크가 하나도 없으면(자주 방문한 사이트와 겹치지 않고 연 적도 없음) 아무것도 고정하지 않고 [고르기] 화면을 연다. (2-9)

    ## 3-6. 새 북마크 정리 — [정리하기] (P2)

    - 2-11의 흐름대로, 새 북마크 수를 버튼에 표시하고 추천 폴더나 직접 고른 폴더로 한 번에 정리한다.

    ---

    ## 3-7. 웹 검색창 — 크롬 기본 검색 유지 (P1)

    - 검색어를 입력하고 Enter를 누르면 chrome.search.query()로 사용자가 크롬에 설정한 기본 검색엔진에서 검색한다.
    - 주소처럼 보이는 입력(http로 시작하거나, 띄어쓰기 없이 점이 들어 있음)은 그 주소로 이동한다.
    - 검색창에 autofocus를 넣지 않아, 새 탭을 열자마자 크롬 주소창에 입력하는 기존 방식이 그대로 동작한다.
    - 검색어 자동완성은 제공하지 않는다. (필요하면 주소창 사용)

    ---

    ## 3-8. 새 탭 첫 화면 배치와 반응형 (P1)

    - 위에서부터 헤더(이름, 내 폴더·모든 북마크로 이동하는 버튼, [정리하기 · N], 정리 기록 버튼) → 날짜 → 웹 검색창 → 첫 정리 카드(있을 때) → 내 폴더(맨 앞에 잊고 있던 북마크 폴더) → 모든 북마크(북마크 검색창 포함) 순으로 배치한다. 고정됨(독)은 화면 아래에 떠 있게 고정한다. (10월 6일 확정 시안)
    - 헤더는 스크롤해도 화면 위에 고정된다. 설정 버튼, 인사말, 날씨, 정렬 메뉴는 두지 않는다.
    - 창 크기에 따라 한 줄에 놓이는 앱·폴더 개수가 자동으로 바뀌고, 가로 스크롤이 생기지 않는다.

    ---

    ## 3-9. 정리 되돌리기 + 정리 기록 화면 (P1 · 정리 기록 화면은 P2)

    - 헤더의 정리 기록 버튼을 누르면 날짜별 정리 내역(예: "9월 30일 첫 정리 · 22개 이동", "10월 3일 새 북마크 정리 · 3개 이동")이 보인다.
    - 내역을 펼치면 북마크별 "원래 위치 → 옮긴 폴더"가 보인다.
    - [되돌리기]를 누르면 그 정리에서 옮긴 북마크가 원래 폴더와 순서로 돌아간다. 그 뒤 사용자가 직접 옮긴 북마크는 건드리지 않는다.
    - 각 북마크를 "원래 순서에서 바로 앞에 있던 북마크"의 바로 뒤에 놓는다. 순서 번호로 되돌리면, 일부가 빠지거나 원래 폴더가 그사이 바뀌었을 때 순서가 뒤섞이기 때문이다. (프로토타입에서 확인)
    - 원래 폴더가 그사이 삭제됐으면 기타 북마크로 되돌리고 그 사실을 알려 준다. 되돌린 뒤 비게 된 폴더는 그 정리가 만든 것만 지운다.
    - 정리 직후 결과 안내에도 [되돌리기]를 둔다.

    ---

    ## 3-10. 북마크 검색 (P2)

    - 모든 북마크 영역 위의 검색창에 입력하면, 제목·주소가 일치하는 북마크가 **검색창 바로 아래에 한 번에** 나타난다. (입력할 때마다 바로 갱신) 확정 시안은 결과를 모든 북마크 영역에 격자로 보여 준다. 리스트(폴더 이름 표시)와 격자 중 어느 쪽으로 할지는 P2를 시작할 때 정한다.
    - 리스트 한 줄에는 사이트 아이콘, 제목, 주소, 들어 있는 폴더가 보이고, 누르면 페이지가 열린다.
    - 폴더 안 북마크까지 찾고, 결과가 없으면 안내 문구를 보여 준다.

    ---

    ## 3-11. 우클릭 폴더 이동 (P2)

    - 앱을 우클릭하면 "새 탭에서 열기", "고정하기", "폴더로 이동" 메뉴가 뜬다.
    - "폴더로 이동"에서 폴더를 고르면 옮겨지고, 크롬 북마크 관리자에도 반영되며, "직접 옮김"으로 기록되어 다음 정리에서 다시 옮기지 않는다.

    ---

    ## 3-12. P3 기능

    - **세부 폴더 제안:** 폴더가 20개를 넘으면, 제목에 반복되는 주제 단어(북마크 3개 이상, 사이트 2곳 이상)로 세부 폴더를 제안한다.
    - **드래그 이동:** 점 6개 손잡이로 앱을 끌어 폴더에 넣거나 순서를 바꾸고, 바꾼 순서는 크롬 북마크에 저장한다. "직접 옮김"으로 기록한다. SortableJS는 순서 바꾸기용이라 "앱을 폴더 아이콘 위에 놓으면 들어감"은 직접 구현해야 한다.

    ## 3-13. 화면 구성

    MVP 화면은 3개 이내로 구성한다. 첫 정리 카드, 앱 폴더, 정리 창은 새 탭 메인 위에 뜨는 팝업이다.

    | 화면 | 내용 |
    | --- | --- |
    | 새 탭 메인 | 헤더, 날짜, 웹 검색창, 내 폴더(잊고 있던 북마크 폴더 포함), 모든 북마크(북마크 검색창), 화면 아래의 고정됨(독) + 첫 정리 카드, 앱 폴더 팝업, 잊고 있던 북마크 팝업, 고정할 북마크 고르기 창 |

    ## 5. MVP 최종 범위

    ### P1 — 11주 중간 데모에서 끝까지 동작

    - 크롬 북마크 자동 동기화
    - 앱 형태 북마크, 앱 폴더(표시와 열기)
    - 새 탭 첫 화면 배치 + 반응형
    - 웹 검색창 (크롬 기본 검색 유지)
    - 분류와 폴더 계획 (북마크바 포함, 요즘 쓰는 북마크 보호)
    - 첫 정리 카드 + 자세히 보기(보기만)
    - 정리 적용 (북마크바에 폴더 만들기, 원래 위치·옮긴 폴더 기록, '옮기는 중' 표시 저장)
    - 정리 결과 안내의 [되돌리기]
    - 잊고 있던 북마크 (8개까지 표시, 열기, 이제 안 봐도 됨, 어디 있는지 보기)

    ### P2 — 15주 최종 데모까지

    - 앱 폴더 만들기·이름 바꾸기·삭제, 폴더 안의 폴더
    - 자세히 보기에서 고치기
    - 직접 옮김 감지 (서비스 워커)
    - 정리 기록 화면
    - 고정됨 (독) + 폴더를 못 만들 때 고정 제안
    - 새 북마크 정리 ([정리하기])
    - 북마크 검색
    - 우클릭 폴더 이동
    - 잊고 있던 북마크의 [고정하기]와 "모두 보기"

    ### P3 — 시간이 남으면

    - 세부 폴더 제안
    - 드래그 이동

    P1의 정리 적용은 '옮기는 중' 표시(pendingMoves)를 처음부터 저장한다. 그러면 P2에서는 서비스 워커만 붙이면 되고 정리 적용 코드를 다시 고치지 않는다.

    ### 확정한 결정 (10월 3일)

    - 주소창으로만 여는 북마크가 "잊고 있던 북마크"에 나오는 한계는 받아들인다. ([이제 안 봐도 됨]으로 뺄 수 있음)
    - 기타 북마크가 계정용·이 PC 전용 두 개면 동기화되는 쪽만 정리한다.
    - 폴더를 지정해 저장한 북마크는 새 북마크로 세지 않는다.
    - 최대 폴더 수는 우리가 만든 폴더 수로 센다.

    ### 정확도 검증 (반복 테스트)

    분류는 서비스의 핵심이므로, 샘플 북마크 세트(10개 미만, 30개, 100개. 대부분 북마크바에 흩어 둠)와 팀이 만든 정답지로 반복 측정하고, 틀린 것을 보고 분류표와 경계 규칙을 고친 뒤 다시 잰다. 폴더 개수·최소 개수 같은 숫자도 이 테스트로 조정한다.

    | 지표 | 뜻 | 방법 |
    | --- | --- | --- |
    | 적용률 | 카테고리가 붙은 비율 | 샘플에서 "분류 안 됨"이 아닌 비율 |
    | 정확도 | 규칙이 의도대로 동작하는가 | 팀 정답지와 비교 |
    | 수정률 | 사용자가 결과를 받아들이는가 | 테스트 참가자가 자세히 보기에서 폴더를 바꾼 비율 |

    ## 7. 정리

    설문 결과, 북마크 사용자 대부분은 북마크를 금방 찾지만, 북마크가 눈에 띄지 않아 **저장한 사실과 저장한 이름을 잊는** 불편이 반복해서 나타났고, 62%는 폴더를 만들지 않았다. 본 프로젝트는 크롬 북마크를 매일 여는 새 탭에 휴대폰 홈 화면처럼 앱과 앱 폴더로 보여 주고, 오래 안 연 북마크를 다시 꺼내 주는 크롬 확장 프로그램을 만든다.

    정리는 북마크 수에 맞춰 많은 카테고리부터 적은 수의 폴더만 한 번 확인 후 만들고, 애매한 북마크는 폴더에 숨기지 않고 새 탭에 보이게 둔다. 북마크가 적으면 폴더 대신 자주 쓰는 북마크를 고정하자고 제안한다. 모든 정리는 외부 AI나 사이트 접속 없이 주소와 제목만으로 이루어지고, 사용자가 만든 폴더와 북마크바에서 요즘 쓰는 북마크는 건드리지 않으며, 원래 위치를 기록해 언제든 되돌릴 수 있다. 새 탭을 대신하지만 크롬 기본 검색은 그대로 쓸 수 있다.
