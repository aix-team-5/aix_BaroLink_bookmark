# 카테고리 정의 문서

> 분류 규칙(`classify.js` 이슈 #7, `categories.json` 이슈 #10, 기능 F05)의 카테고리 정의·경계 규칙과 분류표 내용(10번, 2026-10-07 추가)
> 근거: 서비스 계획(`service-plan.md`) 2-6, 2-7, 기능명세·API명세(`spec.xlsx`) v13의 F05-01 ~ F05-08, N17 `classify`
> 짝이 되는 파일: `extension/data/categories.json`(분류표, 10번을 옮겨 만든다. 한쪽을 고치면 다른 쪽도 함께 고친다), `tests/`의 정답지
> 이 문서의 위치: `docs/category-definitions.md`
> 표기: **제안**은 계획 문서에 없어서 이 문서에서 임시로 정한 내용이다. 9번 표에 모아 두었다. **10월 7일에 9번 표의 제안대로 진행하기로 정했다**(18번, 19번은 9번 표의 결정 열 참고).

이 문서는 "이 북마크는 왜 이 카테고리인가"를 사람이 판단할 때 쓰는 기준이다. 분류표에 사이트를 추가하거나 정답지를 만들 때 이 문서를 먼저 따른다.

---

## 1. 공통 원칙

1. **사이트의 종류로만 정한다.** 페이지 내용(무슨 영상인지, 무슨 글인지)은 보지 않는다. 그래서 사이트 하나는 항상 한 카테고리로만 간다.
2. **주소와 제목만 본다.** 페이지에 접속하지 않는다.
3. **북마크 하나는 카테고리 하나.** 두 카테고리에 걸치는 사이트는 이 문서의 경계 규칙으로 하나를 고른다.
4. **애매하면 분류표에 넣지 않는다.** (제안) 잘못된 폴더에 들어간 북마크는 숨고, 분류 안 된 북마크는 새 탭에 그대로 보인다. 계획서 2-8의 "애매한 북마크는 폴더에 숨기지 않는다"와 같은 방향이다. 적용률보다 정확도를 먼저 챙긴다.
5. **분류 안 됨은 실패가 아니다.** 9개 카테고리에 맞지 않는 사이트(포털 메인, 메일, 지도, AI 도구, 사전, 뉴스 등)는 분류 안 됨이 정답이다.

## 2. 분류 순서와 주소 비교 방법

위에서부터 확인해 **처음 맞는 곳에서 멈춘다.** (F05-01)

| 순서 | 기준 | 근거로 남는 값 (`step`) | 확인 필요 표시 |
|---|---|---|---|
| ① | 사이트 분류표 | `site` | 없음 |
| ② | 주소 끝 규칙 | `suffix` | 없음 |
| ③ | 제목 키워드 | `keyword` | 붙음 (F06-05) |
| ④ | 해당 없음 | 분류 안 됨 (`category: null`) | — |

**분류하지 않는 사이트 (v11 추가).** ①에서 주소가 10-6의 "분류하지 않는 사이트"에 맞으면, ②와 ③을 보지 않고 바로 분류 안 됨으로 정한다. 뉴스 기사나 위키 문서의 제목에 키워드가 우연히 들어 있어 잘못 분류되는 것을 막기 위해서다. 분류표 항목과 함께 비교하고, 여러 항목이 맞으면 더 긴 주소를 따르는 것도 같다.

**주소 비교 방법**

- 주소에서 **호스트**(예: `blog.naver.com`)만 떼어 비교한다. 경로(`/watch?v=…`)는 보지 않는다. (제안: 분류표 항목은 호스트만 적는다)
- 앞의 `www.`는 떼고 비교한다.
- 분류표 항목과 같거나, 그 **하위 주소**면 맞은 것으로 본다. `m.blog.naver.com`은 `blog.naver.com` 항목에, `abc.tistory.com`은 `tistory.com` 항목에 맞는다.
- 여러 항목이 맞으면 **더 긴(구체적인) 주소**를 따른다. `colab.research.google.com`과 `google.com`이 둘 다 있다면 앞의 것을 따른다.
- 주소를 해석할 수 없으면 분류 안 됨이다. (N17)

**이 방법에서 나오는 규칙**

- **포털의 최상위 주소는 분류표에 넣지 않는다.** `naver.com`을 넣으면 지도·메일·웹툰·뉴스까지 전부 그 카테고리로 간다. 네이버·다음·구글·카카오는 서비스별 세부 주소(`blog.naver.com`, `cafe.naver.com`, `docs.google.com`)만 넣는다.
- **`.ac.kr` 주소는 분류표에 넣지 않는다.** 분류표가 주소 끝 규칙보다 먼저라서, 넣으면 "`.ac.kr`이면 내용과 관계없이 학교"가 깨진다.
- **분류표에 있는 사이트는 제목 키워드를 보지 않는다.** 유튜브 영상 제목에 "강의"가 있어도 ①에서 영상으로 끝난다.

## 3. 카테고리별 정의

### 3-1. 학교

| 항목 | 내용 |
|---|---|
| 정의 | 대학·학교가 운영하는 사이트, 그리고 대학 생활에만 쓰는 서비스 |
| 대표 사이트 | `.ac.kr` 전체(학교 홈페이지, 포털, LMS·e-class, 수강신청, 도서관, 학과 홈페이지), 에브리타임 |
| 들어가는 것 | 주소가 `.ac.kr`로 끝나는 모든 페이지. 교수 개인 페이지, 연구실, 학교 도서관, 학교가 운영하는 온라인 강의실도 포함 |
| 안 들어가는 것 | K-MOOC·KOCW(→ 온라인 강의), 대학생 대상 채용·대외활동 사이트(→ 취업), 대학 이름이 들어간 네이버 카페(→ 커뮤니티) |

경계 규칙

- 주소가 `.ac.kr`이면 **내용과 관계없이** 학교다. LMS의 강의 영상 페이지도, 학교 서버에 올린 개인 블로그도 학교다.
- 에브리타임은 형태가 게시판이지만 대학 생활 전용이라 학교로 둔다(계획서 2-7). 정의의 "대학 생활에만 쓰는 서비스"는 이를 담으려고 넓힌 문구다. (제안)
- 한국장학재단은 `.go.kr`이지만 학교로 둔다. 제목 키워드에 "장학 → 학교"가 있는 것과 맞춘 것이다. (제안)
- 학교 LMS가 `.ac.kr`이 아닌 주소에 있으면(외부 업체 주소) ②에 맞지 않는다. 제목에 "학사", "수강신청" 등이 있으면 ③에서 학교가 되고, 없으면 분류 안 됨이다. (알려진 한계)

- 쿠팡플레이(`coupangplay.com`)는 영상, 쿠팡(`coupang.com`)은 쇼핑이다. 회사가 같아도 주소가 다르면 따로 본다.
- TED처럼 강연을 모아 둔 사이트도 강의를 파는 곳이 아니면 영상이다. (제안)

- K-MOOC·KOCW는 대학 강의를 모았지만 주소가 `.ac.kr`이 아니고 강의 제공이 목적이므로 온라인 강의다.

### 3-4. 블로그·글

| 항목 | 내용 |
|---|---|
| 정의 | 개인이 자기 공간에 글을 올리는 사이트 |
| 대표 사이트 | 네이버 블로그, 티스토리, velog, 브런치, Medium, 네이버 포스트, GitHub Pages(`github.io`) |
| 들어가는 것 | 글쓴이 한 명(또는 한 팀)의 공간에 글이 쌓이는 블로그 서비스 |
| 안 들어가는 것 | 여러 사람이 같은 게시판에 올리는 곳(→ 커뮤니티), 뉴스·위키·사전(→ 분류 안 됨), 공식 개발 문서(→ 개발) |

경계 규칙

- **주제와 관계없이 블로그면 여기다.** velog의 알고리즘 풀이 글도, 티스토리의 취업 후기도 블로그·글이다.
- **블로그와 게시판의 구분:** 글이 "한 사람의 공간"에 쌓이면 블로그·글, "모두의 게시판"에 쌓이면 커뮤니티다. 네이버 블로그(`blog.naver.com`)는 블로그·글, 네이버 카페(`cafe.naver.com`)는 커뮤니티다.
- `github.io`는 프로젝트 문서로도 쓰이지만, 대학생이 북마크하는 것은 대부분 기술 블로그라서 블로그·글로 둔다. (제안)
- 자기 도메인을 쓰는 블로그(예: `myname.dev`)는 주소로 알 수 없어 분류 안 됨이다. (알려진 한계)

| 안 들어가는 것 | 메일·캘린더·화상 회의·메신저(→ 분류 안 됨), 코드 저장소(→ 개발), 구글 Colab(→ 개발) |

경계 규칙

- 구글은 서비스별 주소로 나눈다. `docs.google.com`·`drive.google.com`은 문서·협업, `colab.research.google.com`은 개발, 검색(`google.com`)·메일·지도는 분류 안 됨이다.
- 노션에 공개한 페이지(`notion.site`)는 내용이 포트폴리오든 강의 노트든 문서·협업이다.
- 피그마·캔바·미리캔버스 같은 디자인 도구도 "만들고 공유하는 도구"라서 여기에 둔다. 설문 응답자에 디자인 계열 학과가 여럿 있어 넣었다. (제안)

### 3-6. 개발

| 항목 | 내용 |
|---|---|
| 정의 | 코드를 올리거나, 문제를 풀거나, 코드에 대해 찾아보는 사이트 |
| 대표 사이트 | GitHub, GitLab, 백준(`acmicpc.net`), solved.ac, 프로그래머스, LeetCode, Codeforces, SW Expert Academy, Stack Overflow, MDN, 구글 Colab, 캐글, npm, PyPI |
| 들어가는 것 | 코드 저장소, 코딩 테스트·문제 풀이, 공식 개발 문서, 코드 질문·답변, 코드 실행 환경 |
| 안 들어가는 것 | 개발 블로그(→ 블로그·글), 코딩 강의 플랫폼(→ 온라인 강의), YouTube의 코딩 영상(→ 영상), 개발자 채용 사이트(→ 취업) |

경계 규칙

- **"개발에 관한 글"이 아니라 "개발하는 사이트"만 넣는다.** 주제가 코딩이라는 이유만으로 개발에 넣지 않는다.
- 프로그래머스는 강의·채용 메뉴가 있어도 사이트 전체를 개발로 둔다. 대표 용도가 코딩 테스트이기 때문이다.
- Stack Overflow는 여러 사람이 글을 올리지만, 코드 질문·답변이 사이트의 종류 자체라서 개발이다. OKKY 같은 개발자 게시판은 형태가 게시판이므로 커뮤니티로 둔다. (제안)
- `github.com`은 개발, `github.io`는 블로그·글이다. 주소가 다르다.

- 링크드인은 SNS 성격이 있지만 대학생에게는 구직 용도가 커서 취업으로 둔다. (제안)

경계 규칙

- 네이버는 `shopping.naver.com`, `smartstore.naver.com`, `brand.naver.com`만 쇼핑이다.
- 중고 거래와 온라인 서점도 물건을 사는 곳이므로 쇼핑이다. (제안)
- 물건이 아닌 것(영화·공연 예매, 음식 배달, 숙소·항공권)은 분류 안 됨으로 둔다. (제안)

### 3-9. 커뮤니티

| 항목 | 내용 |
|---|---|
| 정의 | 여러 사람이 같은 게시판에 글을 올리는 사이트 |
| 대표 사이트 | 네이버 카페, 다음 카페, 디시인사이드, 레딧, 에펨코리아, 더쿠, 클리앙, 루리웹, 인벤, 뽐뿌, 블라인드, OKKY |
| 들어가는 것 | 게시판·갤러리·카페 형태의 사이트. 주제(게임, 취업, 개발, 쇼핑 정보)는 보지 않는다 |
| 안 들어가는 것 | 에브리타임(→ 학교), Stack Overflow(→ 개발), 인스타그램·X 같은 SNS와 디스코드 같은 메신저(→ 분류 안 됨), 나무위키·위키백과(→ 분류 안 됨) |

경계 규칙

- **주제와 관계없이 게시판이면 여기다.** 블로그·글의 "주제와 관계없이 블로그면 여기"와 짝을 이룬다.
- SNS(인스타그램, X, 페이스북, 스레드)는 게시판이 아니라 개인 피드라서 넣지 않는다. 9개 카테고리 어디에도 맞지 않아 분류 안 됨이다. (제안)
- 위키는 여러 사람이 쓰지만 게시판이 아니라 문서 모음이므로 분류 안 됨이다.

## 5. 제목 키워드

분류표와 주소 끝으로 정하지 못한 북마크에만 적용한다. (계획서 2-7)

| 카테고리 | 키워드 |
|---|---|
| 취업 | 채용, 인턴, 공고, 자소서, 면접 |
| 온라인 강의 | 강의, 강좌, 인강 |
| 학교 | 학사, 수강신청, 수강 신청, 장학, 학과 |
| 개발 | 코딩, 알고리즘, 프로그래밍 |
| 쇼핑 | 구매, 할인, 특가 |

영상, 블로그·글, 문서·협업, 커뮤니티는 키워드가 없다. 이 넷은 제목이 아니라 사이트 형태로 정해지는 카테고리라서, 제목만으로는 알 수 없다.

적용 방법

- 제목에 키워드가 **들어 있으면** 맞은 것으로 본다. **띄어쓰기는 없애지 않고 그대로 비교한다**(10월 7일 확정, 9번 표 18번). 띄어쓰기를 없애면 "꼭 가야 할 인기 맛집"이 "할인"에 걸리는 식의 오분류가 생긴다. 띄어 쓴 표기가 필요하면 키워드에 따로 넣는다(예: "수강 신청"). 영문 키워드를 추가한다면 대소문자를 구분하지 않는다.
- 제목이 여러 카테고리의 키워드에 맞으면 `categories.json`에 **먼저 적힌 카테고리**를 따른다. (제안. 예: "인턴 대비 알고리즘 강의"는 취업·개발·온라인 강의에 모두 맞는다)
- 키워드로 정해진 북마크는 항상 "확인 필요"가 붙는다. (F06-05)

알려진 오분류 (정답지에 일부러 넣어 수치로 확인한다)

| 제목 예 | 키워드 | 붙는 카테고리 | 실제 |
|---|---|---|---|
| 컴퓨터공학과 - 나무위키 | 학과 | 학교 | 위키 문서 |
| 수학과 과학의 역사 | 학과 ("수**학과**") | 학교 | 관계없음 |
| 항공사 특가 경쟁 과열 (뉴스 기사) | 특가 | 쇼핑 | 뉴스 기사 |
| 신뢰를 공고히 하는 법 | 공고 | 취업 | 관계없음 |

v11부터 나무위키와 네이버 뉴스처럼 10-6에 있는 사이트는 제목 키워드를 보지 않으므로 위 표의 오분류가 생기지 않는다. 같은 제목이 다른 사이트에 있으면 여전히 오분류되고, "확인 필요"로 알린다.

## 6. 분류 안 됨이 정답인 사이트

9개 카테고리에 맞지 않아 분류표에 넣지 않는 종류다. 제목 키워드에 걸리지 않는 한 분류 안 됨이 된다. 이 가운데 뉴스, 위키·지식, 검색 결과는 10-6의 "분류하지 않는 사이트"에 넣어 제목 키워드도 보지 않게 했다(v11).

| 종류 | 예 |
|---|---|
| 포털·검색 | 네이버 메인, 구글 검색, 다음 메인 |
| 메일·캘린더 | Gmail, 네이버 메일, 구글 캘린더 |
| AI 도구 | ChatGPT, Claude, Gemini, 뤼튼, 퍼플렉시티 |
| 번역·사전 | 파파고, DeepL, 네이버 사전 |
| 논문·학술 검색 | RISS, DBpia, 구글 학술검색 |
| 위키·지식 | 나무위키, 위키백과, 네이버 지식iN |
| 뉴스 | 네이버 뉴스, 언론사 사이트 |
| SNS·메신저·회의 | 인스타그램, X, 디스코드, 카카오톡 웹, Zoom |
| 지도·교통·예매 | 네이버 지도, 카카오맵, 코레일, 영화 예매 |
| 금융·공공 | 은행, 토스, 정부24, 홈택스 |
| 웹툰·음악·게임 | 네이버 웹툰, 멜론, 스팀 |
| 주소로 알 수 없는 것 | 자기 도메인 블로그, 회사 홈페이지, `localhost`, IP 주소, `file://` |

AI 도구와 논문 검색은 대학생이 자주 북마크하는 종류인데 맞는 카테고리가 없다. 첫 측정에서 분류 안 됨 중 이 둘의 비율을 따로 세어 보고, 높으면 카테고리 추가를 검토한다. (제안)

## 8. 분류표에 사이트를 추가할 때

1. 사이트의 **형태**를 본다: 동영상을 보는 곳인가, 강의를 파는 곳인가, 한 사람의 글 공간인가, 모두의 게시판인가, 문서를 만드는 도구인가, 코드를 다루는 곳인가, 공고를 보는 곳인가, 물건을 사는 곳인가.
2. 3번의 "안 들어가는 것"과 경계 규칙에 걸리는지 확인한다.
3. 두 카테고리 사이에서 정하지 못하면 넣지 않는다. (원칙 4)
4. 주소는 `www.`를 뗀 호스트로 적는다. 포털 최상위 주소와 `.ac.kr` 주소는 넣지 않는다.
5. 새 항목이 기존 항목의 하위 주소면(예: `google.com` 계열) 더 긴 쪽이 이긴다는 것을 생각하고 넣는다.
6. 추가한 뒤 정답지로 다시 잰다. (N18 `measure`)

| ③ 제목 키워드 | 강의, 강좌, 인강 | 온라인 강의 | 맞으면 "확인 필요" (F06-05) |
| ③ 제목 키워드 | 코딩, 알고리즘, 프로그래밍 | 개발 | 맞으면 "확인 필요" (F06-05) |
| ③ 제목 키워드 | 채용, 인턴, 공고, 자소서, 면접 | 취업 | 맞으면 "확인 필요" (F06-05) |
| ③ 제목 키워드 | 구매, 할인, 특가 | 쇼핑 | 맞으면 "확인 필요" (F06-05) |

영상, 블로그·글, 문서·협업, 커뮤니티는 키워드가 없다 (5번). 영문 키워드는 아직 넣지 않았다.

### 10-4. 일부러 넣지 않은 사이트

대학생이 자주 쓰지만 원칙 4(애매하면 넣지 않는다)나 주소 비교 방법 때문에 뺀 것이다. 넣자는 의견이 나오면 이 표에서 옮긴다.

| 사이트 | 주소 | 넣지 않은 이유 |
|---|---|---|
| 오늘의집 | `ohou.se` | 쇼핑과 커뮤니티(집들이 글)가 섞여 있다 |
| 인터파크 | `interpark.com` | 쇼핑·공연 예매·여행이 섞여 있다. 예매·여행은 분류 안 됨(제안 #11) |
| 마이크로소프트 오피스 웹 | `office.com` | 넣으면 하위 주소인 `outlook.office.com`(메일)까지 문서·협업이 된다. 원드라이브·셰어포인트만 넣었다 |
| 구글 사이트 | `sites.google.com` | 만든 사람마다 용도가 다르다 (학과 홈페이지, 포트폴리오, 동아리) |

| 배포된 개인 사이트 | `vercel.app`, `netlify.app`, `web.app` | 남이 만든 사이트라 종류를 알 수 없다 |
| 포털 최상위 주소 | `naver.com`, `daum.net`, `google.com`, `kakao.com` | 2번 규칙. 지도·메일·뉴스까지 끌려 들어간다 |

### 10-5. `categories.json`으로 옮길 때

형식은 N17 `classify(bookmark, categories)`와 F05-01 ~ F05-03에 맞춘 제안이다. JSON에는 주석을 달 수 없으므로 비고와 제안 번호는 이 문서에만 둔다.

```json
{
  "categories": [
    {
      "name": "학교",
      "sites": ["everytime.kr", "kosaf.go.kr"],
      "suffixes": [".ac.kr", ".edu"],
      "keywords": ["학사", "수강신청", "수강 신청", "장학", "학과"]
    },
    {
      "name": "영상",
      "sites": ["youtube.com", "youtu.be", "…"],
      "suffixes": [],
      "keywords": []
    }
  ],
  "noCategorySites": ["news.naver.com", "namu.wiki", "…"]
}
```

- `categories` 배열의 순서 = 10-1의 순서. 이 배열 순서가 동점 기준이다.
- `name`은 폴더 이름으로도 쓰이므로 10-1의 표기(가운뎃점 `·` 포함)를 그대로 쓴다.
- 한 주소는 한 카테고리에만 넣는다. 같은 주소가 두 번 나오면 안 된다.
- 하위 주소 비교는 **점(.) 단위**로 한다. 호스트가 항목과 같거나 `"." + 항목`으로 끝날 때만 맞는다. 글자 끝만 비교하면 `coupangeats.com`이 `coupang.com`에 맞아 버린다. 주소 끝 규칙도 같다.
- `noCategorySites`는 10-6의 "분류하지 않는 사이트"다. ①에서 분류표 항목과 함께 비교해, 가장 긴 주소로 맞은 것이 이 목록이면 `{ category: null }`을 돌려주고 멈춘다 (v11).
- 제목 키워드는 제목을 그대로 두고 비교한다. 띄어쓰기를 없애지 않는다 (v11).
- N17이 돌려주는 `rule`에는 맞은 값(주소, 주소 끝, 키워드)을 그대로 넣는다. `step`이 `keyword`면 `needsCheck: true`.

**확인한 것** (2026-10-07): 7번 예시 43개와 아래 8개를 이 표로 분류해 보면 모두 문서에 적힌 결과와 같다.

| 북마크 (제목 · 주소) | 결과 | 확인한 규칙 |
|---|---|---|
| AWS 콘솔 · `console.aws.amazon.com/…` | 개발 | `aws.amazon.com`이 `amazon.com`보다 길어서 이김 |
| 쿠팡이츠 · `coupangeats.com` | 분류 안 됨 | 점 단위 비교. `coupang.com`에 맞지 않음 |
| 점핏 · `jumpit.saramin.co.kr/…` | 취업 | 하위 주소 |
| Outlook 메일 · `outlook.office.com/mail` | 분류 안 됨 | `office.com`을 넣지 않은 이유 |
| 인턴 대비 알고리즘 강의 · `example.com` | 온라인 강의 | 키워드 동점은 10-1 순서 |
| 항공사 특가 경쟁 과열 - 네이버 뉴스 · `n.news.naver.com/…` | 분류 안 됨 | 분류하지 않는 사이트 (v11). 제목의 "특가"를 보지 않음 |
| 수강 신청 안내 · `example.com` | 학교 | 띄어 쓴 키워드 "수강 신청" (v11) |
| 꼭 가야 할 인기 맛집 · `example.com` | 분류 안 됨 | 띄어쓰기를 없애지 않으므로 "할인"에 걸리지 않음 (v11) |

### 10-6. 분류하지 않는 사이트 (v11 추가, `noCategorySites`)

주소가 아래에 맞으면 주소 끝 규칙과 제목 키워드를 보지 않고 분류 안 됨으로 정한다 (2번). 9개 카테고리에 들어가지 않으면서, 제목에 키워드가 우연히 들어가기 쉬운 사이트만 넣는다. 처음에는 뉴스, 위키·지식, 검색 결과만 넣었다.

| 주소 | 사이트 | 종류 |
|---|---|---|
| `news.naver.com` | 네이버 뉴스 (n.news.naver.com, m.news.naver.com 포함) | 뉴스 |
| `news.daum.net` | 다음 뉴스 | 뉴스 |
| `v.daum.net` | 다음 뉴스 기사 주소 | 뉴스 |
| `news.google.com` | 구글 뉴스 | 뉴스 |
| `namu.wiki` | 나무위키 | 위키·지식 |
| `wikipedia.org` | 위키백과 (ko.wikipedia.org 포함) | 위키·지식 |
| `kin.naver.com` | 네이버 지식iN | 위키·지식 |
| `search.naver.com` | 네이버 검색 결과 | 검색 결과 |
| `search.daum.net` | 다음 검색 결과 | 검색 결과 |

- 포털 최상위 주소(`naver.com`, `google.com`)는 여기에도 넣지 않는다. 넣으면 그 아래의 모든 서비스가 제목 키워드를 못 쓰게 된다.
- 분류표의 사이트보다 더 긴 주소를 넣으면 그 부분만 분류 안 됨으로 뺄 수 있다. 예: `ticket.yes24.com`을 넣으면 예매는 분류 안 됨, 나머지 `yes24.com`은 쇼핑이 된다. (아직 넣지 않았다. 제안 #11과 함께 검토)
- 넣을지 검토할 후보: AI 도구(대화 제목이 북마크 제목이 되어 키워드에 걸리기 쉽다), 언론사 사이트.
- 샘플 100개 기준으로 이 목록을 넣기 전후: 적용률 92% → 89%, 정확도 96.7% → 100%, 전체 일치 96% → 99%.
